### 一、什么是采样? (What is Sampling?)

在大模型自回归(Autoregressive)文本生成的每一步(Decode Step)中, Transformer 的最后一层会输出一个维度为 $|V|$ 的未归一化实数向量, 即 Logits($z \in \mathbb{R}^{|V|}$, 其中 $|V|$ 为词表大小, 常见如 32,000 到 150,000 不等).

随后, 通常会通过 Softmax 函数将 Logits 映射为一个离散的概率分布:

$$P(w_t = v_i \mid w_{<t}) = \frac{\exp(z_i)}{\sum_{j=1}^{|V|} \exp(z_j)}$$

采样(Sampling), 广义上指从这个高维概率分布 $P$ 中挑选出下一个 Token 的解码决策策略; 狭义上特指依据随机性(Stochasticity)的多项式采样策略(相对于确定性选取最大概率的贪心策略).

#### 从 vLLM 系统底层的视角来看:

在推理引擎中, 采样并不仅仅是一个数学公式, 它是 Decode 阶段极其敏感的 Logit 算子瓶颈. 如果 batch size 为 128, 词表大小为 128k, 每一步生成的 Logits 矩阵就高达数十兆字节. vLLM 的 `Sampler` 会在 GPU 上通过高度优化的 Fused CUDA/Triton Kernel, 将惩罚项计算、截断、Softmax、多项式采样融合成极少次的 GPU 显存往返(Memory Round-trip), 并将采出的单个 Token ID 快速写回 KV Cache 分配流中.

---

### 二、为什么需要采样? (Why Sampling?)

为什么我们不能总是简单粗暴地挑概率最大的词(即 Greedy Search / 贪心搜索, $\arg\max_i P_i$)?

1. 避免文本退化与无限死循环(Degeneration & Repetition Loop)
   * 信息论与语言学研究(如著名的 The Curious Case of Neural Text Degeneration)表明, 人类自然语言并不会始终选择"条件概率最高"的词. 如果纯粹使用贪心搜索, 模型极容易陷入自相关陷阱 -- 生成极度单调、重复、车轱辘话的文本, 甚至无限死循环.

2. 平衡多样性与创造力(Diversity vs. Coherence)
   * 在开放式对话、头脑风暴、文学创作以及角色扮演等场景下, 需要输出具有丰富度、惊喜感和探索性的回答; 在合成数据生成(如 Self-Instruct、RLHF 的多样性负例采样)中, 非确定性采样也是必不可少的.

3. 人类语言的高低熵动态特征(Entropy Fluctuations)
   * 人类说话时, 信息的密集度是动态起伏的. 有些语境确定性极强(例如"中华人民共和国的首都", 下一个词基本只能是"北"), 而有些语境极其开放(例如"他走进房间, 突然看到……"). 采样机制允许模型在不确定性高的情境下进行合理的发散探索.

4. 为何现代引擎偏向采样而非束搜索(Beam Search)?
   * 在早期的机器翻译中, 维持多条候选路径的 Beam Search 很常见. 但在 LLM 时代:
     * 工程代价极高: Beam Search 需要在步骤间分裂、合并假设路径, 这与 vLLM 的 PagedAttention 和连续批处理(Continuous Batching)机制高度冲突, 会导致严重的显存碎片化和复杂的 KV Cache 复制.
     * 生成质量"平庸": Beam Search 在长文本生成中容易产出极其平庸、概率虽高但不像人话的"假空"文本. 随机采样在结合了截断策略后, 质量和吞吐往往远胜 Beam Search.

---

### 三、常见的采样方式有哪些?

在现代大模型推理框架中, 采样方式通常以"流水线"(Pipeline)的形式组合运作: Logit 调整 $\to$ 截断过滤 $\to$ 最终抽取.

#### 1. 基础确定性采样

* Greedy Decoding(贪心采样):
  * 机制: 直接取 $x_t = \arg\max_i (z_i)$.
  * 适用场景: 数学计算、代码生成、确定性推理(如 GSM8K、HumanEval 评测). 在 vLLM 中, 通常将 `temperature=0` 直接映射为贪心解码, 省去随机数生成逻辑.

#### 2. 分布缩放(Distribution Shaping)

* Temperature(温度采样, $\tau$ 或 $T$):
  * 机制: 在执行 Softmax 前缩放 Logits: $P_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$.
  * 表现:
    * $T \to 0$: 分布趋于极度尖锐(One-hot), 等价于 Greedy Search.
    * $T < 1$(如 0.7): 降低低概率词的权重, 提升回答的严谨性和聚焦度.
    * $T > 1$: 将分布拉平, 提高长尾冷门词被采中的概率, 增加天马行空的想象力, 但过高会导致胡言乱语(Hallucination / Gibberish).

#### 3. 截断类采样(Truncation / Filtering) -- 消除分布的长尾毒性

纯随机采样容易抽到词表中概率极低但非零的异常 Token(如特殊标点、无意义词), 因此必须引入截断.

* Top-$k$ Sampling:
  * 机制: 保留概率最高的前 $k$ 个候选 Token, 将剩余词的 Logit 置为 $-\infty$, 再重新归一化采样.
  * 缺点: $k$ 是静态常数. 当分布本身非常平坦时(需要更多选择), $k$ 可能限制了创意; 当分布极尖锐(只有一两个词合情合理)时, $k$ 又会把垃圾词强行纳入候选池.

* Top-$p$ Sampling(Nucleus Sampling / 核心采样):
  * 机制: 动态计算降序排列的累积概率, 只保留累积概率刚刚达到阈值 $p$(通常 0.8~0.95)的最小 Token 集合.
  * 优点: 能够根据上下文的不确定度自适应调整候选池大小. 上下文确定时候选词少, 开放时候选词多, 是目前工业界最常用的主力采样器之一.

* Min-$p$ Sampling(近年来备受推崇的新截断策略):
  * 机制: 设最大概率为 $P_{max} = \max_j P_j$. 仅保留满足 $P_i \ge \text{Min-}p \times P_{max}$ 的 Token.
  * 对比 Top-$p$ 的优势: 在极端确定场景($P_{max} = 0.99$), 如果 Min-$p=0.1$, 则只有概率大于 $0.099$ 的词能留下, 瞬间剪除杂质; 而在平坦场景, 所有与最高概率差距不大的词均被保留. 相比 Top-$p$, Min-$p$ 在保持多样性的同时, 极大地降低了崩坏和胡言乱语率. 目前 vLLM 已原生支持该参数.

#### 4. 惩罚项机制(Logit Penalties)

采样前对部分 Token 的 Logits 施加显式打压:

* Repetition Penalty(重复惩罚):
  * 对已经生成过的 Token 的 Logit 乘以或除以衰减系数 $\alpha > 1$.
* Frequency & Presence Penalty(频率与存在惩罚):
  * 源自 OpenAI API 的标准机制.
  * $z_i' = z_i - (\text{presence\_penalty} \times \mathbb{I}(c_i > 0) + \text{frequency\_penalty} \times c_i)$, 其中 $c_i$ 为 Token $i$ 在已生成文本中的出现频次. Presence 惩罚"是否出现过", 鼓励换新话题; Frequency 惩罚"出现过的次数", 防止复读.

#### 5. 现代前沿采样策略(Advanced Inference Techniques)

* Speculative Decoding 中的 Rejection Sampling(投机采样中的拒绝采样):
  * 投机推理(如 Small Draft Model + Large Target Model)依赖改进的拒绝采样机制: 利用概率比值 $P_{target}(x) / P_{draft}(x)$ 决定是否接收 Draft Token, 在严格保证输出分布与纯大模型采样完全一致的前提下, 将推理延迟降低 2~3 倍.
* Guided Decoding / Structured Sampling(结构化采样, 如 JSON 约束):
  * 如 vLLM 集成的 Outlines 或 XGrammar. 基于上下文无关文法(CFG)或正则表达式构建有限状态机(FSM), 在每一步采样前, 将所有违反语法规则的 Token 的 Logits 直接掩码为 $-\infty$, 确保生成的输出 100% 符合 JSON/SQL 等特定 Schema.

作为一个系统框架层面的实践者, 给出的落地建议通常如下:

| 任务场景                        | 推荐配置范式                                         | 核心诉求                         |

## 1. 假设你是一位精通 LLM 的高级研究人员, 在 Prompt 提示工程中, 经常看到一些参数 Temperature, Top-k, Top-p, Min-p 等, 请使用具体的示例说明这些参数的含义.

你好! 作为一名 LLM 研究人员, 我非常乐意为你解答这个问题.

在探讨这些参数之前, 我们需要先建立一个核心共识: 大语言模型的本质是一个"接话把子". 在每一步生成时, 模型实际上并没有直接输出一个确定的词, 而是对词表中的几万个 Token 计算出一个概率分布(Probability Distribution).

为了让你直观理解, 我们设定一个具体的实验场景:

假设输入 Prompt 是: "`今天天气真好, 我们一起去`"

此时, 模型为下一个 Token 预测的初始概率分布如下:
* 爬山: 50% (0.50)
* 散步: 30% (0.30)
* 逛街: 15% (0.15)
* 火星: 4% (0.04)
* 跳海: 1% (0.01)

接下来, 我们看看 `Temperature`、`Top-k`、`Top-p` 和 `Min-p` 是如何在这个概率分布上"动刀子"的.

---

### 1. Temperature (温度) -- 调节"平庸"与"疯狂"

含义: Temperature 并不改变 Token 概率的排名, 而是改变概率分布的"陡峭程度". 它作用于模型输出的 Logits(未归一化的得分)输入 Softmax 函数之前.

* T < 1(降温): 放大强者, 抑制弱者. 概率分布变陡峭.
* T = 1: 原始概率分布.
* T > 1(升温): 缩小差距, 大家都有机会. 概率分布变平缓.

具体示例:

* T = 0.1(极低, 适合代码生成、数学推理):
  "爬山"的概率会被放大到 99%, "散步"变为 1%, 其他变为 0. 模型变得非常死板、确信, 每次测试都会输出"爬山". (当 T=0 时, 等同于 Greedy Search 贪婪搜索).
* T = 1.5(极高, 适合头脑风暴、创意写作):
  原本 50% 的"爬山"可能降到 35%, 原本 4% 的"火星"可能升到 15%. 此时模型就有不小的概率蹦出"今天天气真好, 我们一起去火星"这种极具创意的回答.

---

### 2. Top-k -- 简单粗暴的"末位淘汰"

含义: 在采样前, 直接把概率排名前 k 个之外的 Token 剔除, 然后在剩下的 k 个 Token 中重新分配概率(归一化).

具体示例(假设设置 Top-k = 2):

* 在我们的词表中, 前 2 名是"爬山"(50%) 和"散步"(30%).
* 剩下的"逛街"、"火星"、"跳海"全部被直接砍掉, 哪怕逛街有 15% 的概率也被无情抛弃.
* 剩下的两人重新瓜分 100% 的概率: "爬山"变成 $\frac{50}{50+30} = 62.5\%$, "散步"变成 $\frac{30}{50+30} = 37.5\%$.

研究员点评: Top-k 的缺点是缺乏弹性. 有时候模型对前 5 个词都很犹豫(概率都很接近), Top-k=2 会错杀合理选项; 有时候模型对第 1 个词极度确信(概率 90%), Top-k=2 却硬拉第 2 个词进来陪跑.

---

### 3. Top-p (Nucleus Sampling 核采样) -- 动态的"及格线"

含义: 按概率从大到小累加, 当累加概率刚刚超过阈值 p 时, 截断后面的词表. 这是一种"动态截断"策略.

具体示例(假设设置 Top-p = 0.90):

我们开始累加概率:

1. 第一名"爬山": 累加 0.50(未达到 0.90)
2. 第二名"散步": 累加 0.50 + 0.30 = 0.80(未达到 0.90)
3. 第三名"逛街": 累加 0.80 + 0.15 = 0.95(超过 0.90! 触发截断)
*  结果: 保留"爬山"、"散步"、"逛街", 剔除后面的"火星"、"跳海". 这三个词按比例重新归一化.

研究员点评: Top-p 比 Top-k 聪明得多. 如果模型很确信(比如第一个词概率就有 95%), Top-p=0.90 就会只保留这 1 个词; 如果模型很犹豫(词汇概率都很小), Top-p 可能会保留几十个词, 保证了多样性.

---

### 4. Min-p -- 关注"相对实力"的新锐参数

含义: Min-p 是近期(特别是在 llama.cpp 等开源社区中)越来越受推崇的参数. 它的逻辑是: 以当前最高概率的 Token 为基准, 乘以 Min-p 阈值, 计算出一条底线. 凡是低于这条底线的 Token 全部淘汰.

具体示例(假设设置 Min-p = 0.10):

* 场景 A(模型很确信): 最高概率是"爬山"(0.50). 底线 = $0.50 \times 0.10 = 0.05$ (5%).
  * 筛查: "爬山"(50%)、"散步"(30%)、"逛街"(15%) 均大于 5%, 保留. "火星"(4%)、"跳海"(1%) 小于 5%, 被淘汰.

* 场景 B(模型很犹豫, 词汇很分散): 假设此时最高概率的词只有 20% (0.20). 底线 = $0.20 \times 0.10 = 0.02$ (2%).
  * 此时, 所有概率大于 2% 的长尾词汇都会被保留.

研究员点评: Top-p 有一个隐患: 当模型对前几个词完全不确信(比如有 100 个概率为 1% 的词), Top-p 会把一大堆毫无关联的"垃圾词汇"纳入采样池. 而 Min-p 动态地锚定了"最可能的那个词", 能够极其精准地剔除"与最可能词相比, 显得太弱小"的离谱词汇, 生成质量往往比 Top-p 更稳定.

---

### 高级研究员的实操建议 (Best Practices)

在大多数推理框架(如 vLLM, HuggingFace Transformers)中, 这些参数是可以组合使用的, 它们的生效顺序通常是: `Temperature -> Top-k -> Top-p -> Min-p`.

* 逻辑推理 / 写代码 / 信息抽取:

  * 设为 `Temperature = 0`(或者极低如 0.1), 其他参数不用管. 我们需要绝对的确定性.

* 日常对话 / 写文章 / 角色扮演:
  * 经典组合: `Temperature = 0.7`, `Top-p = 0.9`. 这能保证文本既通顺又有一定的灵动性.
  * 前沿推荐: 弃用 Top-k 和 Top-p, 尝试 `Temperature = 1.0` 配合 `Min-p = 0.05`. 你会发现模型生成的词汇非常丰富, 但同时又极少出现乱码或逻辑崩塌的幻觉.

## 2. 感谢您对参数 Temperature, Top-k, Top-p, Min-p 的精彩解释, 我自信能很好的理解这些内容, 不过我还是有些疑问, 对于 Temperature 参数, 是通过怎样的计算算出新的概率分布的, 请还是以上面的爬山、散步、逛街、火星、跳海示例为例, 说明一些具体的计算过程

这是一个非常硬核且极具钻研精神的好问题! 能够深入到数学公式层面去理解大模型, 是成为顶尖 AI 研究人员的必经之路.

要计算 Temperature(温度)如何改变概率, 我们需要引入大模型输出层的核心公式: 带温度参数的 Softmax 函数.

### 1. 核心公式与前置知识

大语言模型在最后一层(通常是 Linear 层)输出的, 并不是直接的概率(0~100%), 而是一组没有边界的原始得分, 被称为 Logits(记为 $z$).

我们看到的那组概率, 是 Logits 经过 Softmax 函数转换后得到的. 加入 Temperature ($T$) 后的公式如下:

$$ P_i = \frac{e^{(z_i / T)}}{\sum_{j} e^{(z_j / T)}} $$

* $z_i$: 第 $i$ 个词的原始得分 (Logit).
* $T$: 温度参数 (Temperature).
* $e$: 自然常数 (约等于 2.718).
* 分母: 所有词经过 $e^{(z/T)}$ 计算后的总和(用于归一化, 确保最终概率加起来等于 100%).

---

### 2. 逆推原始得分 (Logits)

在我们之前的例子中, 已知初始概率 ($T=1$) 是: 爬山 50%, 散步 30%, 逛街 15%, 火星 4%, 跳海 1%.

为了演示计算过程, 我们需要先通过自然对数 $\ln(p)$ 逆推出它们大概的原始得分 (Logits).

* 爬山: $z_1 = \ln(0.50) \approx -0.693$
* 散步: $z_2 = \ln(0.30) \approx -1.204$
* 逛街: $z_3 = \ln(0.15) \approx -1.897$
* 火星: $z_4 = \ln(0.04) \approx -3.219$
* 跳海: $z_5 = \ln(0.01) \approx -4.605$

接下来, 我们来看看当 $T$ 发生改变时, 魔法是如何发生的.

---

### 3. 具体计算推演

#### 场景 A: 降温(确信模式), 设置 $T = 0.5$

公式变为把原来的 Logits 除以 0.5(相当于乘以 2), 拉开了得分之间的差距.

| 词汇 | 原始 $z$ | $z / T$ ($z / 0.5$) | 指数运算 $e^{(z/T)}$                 | 重新归一化 (除以总和) | 最终新概率       |
| :--- | :------- | :------------------ | :----------------------------------- | :-------------------- | :--------------- |
| 爬山 | -0.693   | -1.386              | $e^{-1.386} \approx \mathbf{0.2500}$ | $0.2500 / 0.3642$     | 68.6% (上升↑)    |
| 散步 | -1.204   | -2.408              | $e^{-2.408} \approx \mathbf{0.0900}$ | $0.0900 / 0.3642$     | 24.7% (下降↓)    |
| 逛街 | -1.897   | -3.794              | $e^{-3.794} \approx \mathbf{0.0225}$ | $0.0225 / 0.3642$     | 6.2% (下降↓)     |
| 火星 | -3.219   | -6.438              | $e^{-6.438} \approx \mathbf{0.0016}$ | $0.0016 / 0.3642$     | 0.4% (惨遭碾压)  |
| 跳海 | -4.605   | -9.210              | $e^{-9.210} \approx \mathbf{0.0001}$ | $0.0001 / 0.3642$     | 0.03% (几乎消失) |

* 结论: 当 $T < 1$ 时, 大者恒大. 原本 50% 的"爬山"吸走了其他选项的生存空间, 暴涨到了 68.6%. 长尾词汇被极度压缩.

### 研究员的终极总结

通过上面的数学计算, 我们可以提炼出 Temperature 的本质原理:

Temperature 其实是在操控指数函数 $e^x$ 的输入量级.

* 指数函数是一个非常敏感的非线性函数(输入稍微变大一点, 输出就会爆炸; 输入稍微变小一点, 输出就会归零).

* 当 $T$ 趋近于 $0$(例如 $T=0.001$), Logits 的差距会被无限放大, 最高分的 Token 经过指数运算后会一柱擎天, 占比 99.999%, 等价于贪婪搜索(Greedy Search).

* 当 $T$ 趋近于无穷大, Logits 除以无限大后全部变成 0, 而 $e^0 = 1$. 此时所有几万个词汇的概率全部变成均等的 $\frac{1}{N}$, 等价于完全随机瞎猜.

这就是为什么调整哪怕 $0.1$ 的 Temperature, 都会对大模型的生成语气和逻辑严谨度产生肉眼可见的影响的原因.

投机采样(Speculative Decoding / Speculative Sampling)是近年来大语言模型(LLM)推理加速领域最具里程碑意义的技术之一.

如果用一句话概括它的本质: 它利用低成本的机制先"猜测"未来的一串 Token, 再由大模型单次前向传播进行"并行验证"; 在数学上能完全保证输出分布与原大模型 100% 一致(无损), 却能将端到端推理速度提升 2 到 3 倍.

下面作为系统研究人员, 我从硬件底层瓶颈、具体算法流程、数学无损性原理以及 vLLM 工程实现四个层面为你彻底剖析这项技术.

### 一、为什么需要投机采样? (底层驱动力)

要理解投机采样, 必须先明白现代 GPU 跑大模型推理时的真正痛点: 显存带宽瓶颈(Memory-Bound).

#### 1. 传统自回归解码的"算力灾难"

以一个 70B 参数的 FP16 模型为例, 参数量约 140 GB. 在标准自回归生成中, 生成一个 Token 的过程如下:

* 必须把 140 GB 权重从 GPU 显存(HBM)完整读取到计算核心(SRAM/Tensor Core)一遍.
* 每读进一个权重矩阵, 却只和一个形状为 $[1, \text{hidden\_dim}]$ 的单向量做矩阵向量乘法(GEMV).
* 算术强度(Arithmetic Intensity)极低: 算力利用率(MFU)通常只有个位数. 现代 GPU(如 H100/A100)极其恐怖的每秒千万亿次浮点算力(TFLOPS)绝大部分时间都在"干等"显存搬运数据.

#### 2. "验证"远比"思考"容易

既然大模型每次加载完整权重需要消耗固定时间, 那么:
* 生成 1 个 Token: 需要完整读取一次 70B 模型权重.
* 验证 5 个已知 Token: 将这 5 个 Token 拼成矩阵一次性送入(GEMM 运算), 计算核心的并行度上来了, 耗费的时间和生成 1 个 Token 几乎一模一样!

#### 3. 自然语言的冗余度

人类语言中有很多"废话"或极其容易预测的高频搭配(例如短语"Artificial Intelligence"、代码中的 `for (int i = 0; i < n; i++)`、套话"总而言之"). 这些简单的过渡词, 根本不需要一个 70B 参数的大脑花费巨大的代价逐字推敲.

因此, 投机采样的直觉非常朴素: 让一个便宜的小模型(如 1B~7B)充当"速记员"快速往前推测若干词, 然后让 70B 大模型充当"主考官", 看一眼就批量并行打勾或纠错.

### 二、投机采样的具体执行过程

我们定义:

* 目标模型(Target Model, $M_p$): 我们要加速的高性能大模型, 其输出概率分布记为 $P(x)$.
* 草稿模型(Draft Model, $M_q$): 速度极快的小模型, 其输出概率分布记为 $Q(x)$.
* 投机步长(Speculation Window, $K$): 每轮小模型猜测的 Token 数量(通常取 $K=3 \sim 6$).

一个完整的投机循环(Speculation Loop)包含以下四个步骤:

```
                    ┌──────────────────────────────┐
                    │ 1. Draft 阶段 (小模型自回归生成) │
                    └──────────────┬───────────────┘
                                   │ 猜出 K 个 Token: [x₁, x₂, ..., xₖ]
                                   ▼
                    ┌──────────────────────────────┐
                    │ 2. Target 阶段 (大模型并行验证)│ (1次前向传播计算全部 Logits)
                    └──────────────┬───────────────┘
                                   │
                                   ▼
              ┌────────────────────────────────────────┐
              │ 3. 修正拒绝采样 (Rejection Sampling)   │
              └──────────────┬──────────────────┬──────┘
                             │ 接受前 m 个      │ 拒绝第 m+1 个
                             ▼                  ▼
                    ┌────────────────┐  ┌─────────────────────────┐
                    │ 采纳 [x₁...xₘ] │  │ 大模型残差分布重采样纠错 │
                    └────────────────┘  └───────────┬─────────────┘
                                                    │
                                                    ▼
                                         ┌─────────────────────┐
                                         │ 4. KV Cache 状态回滚 │
                                         └─────────────────────┘
```

#### Step 1: 草稿生成(Drafting)

小模型 $M_q$ 基于当前上下文, 像普通自回归一样, 串行生成 $K$ 个草稿 Token:

$$\tilde{x}_1, \tilde{x}_2, \dots, \tilde{x}_K$$

在此过程中, 小模型记录每一步它抽中这些词的概率 $Q(\tilde{x}_1), Q(\tilde{x}_2), \dots, Q(\tilde{x}_K)$. 因为小模型体量极小, 这 $K$ 步耗时极短.

#### Step 2: 目标模型并行验证(Verification)

我们将原上下文连同这 $K$ 个候选 Token, 一次性输入目标大模型 $M_p$ 执行单次 Forward Pass.
这一步类似于 Prefill 阶段, 大模型由于一次性看到了 $K$ 个位置, 会并行产出 $K+1$ 个条件分布:

$$P(\cdot \mid \text{prefix}), \quad P(\cdot \mid \text{prefix}, \tilde{x}_1), \quad \dots, \quad P(\cdot \mid \text{prefix}, \tilde{x}_1 \dots \tilde{x}_K)$$

#### Step 3: 修正拒绝采样(Modified Rejection Sampling)

这是投机采样最精妙的地方 -- 如何做到加速却完全不损失大模型原版的数学精度?
主考官按顺序依次审查每一个候选词 $\tilde{x}_i$(从 $i = 1$ 到 $K$):

1. 从均匀分布中抽取随机数 $r \sim U(0, 1)$.

2. 比较判定:
   * 如果 $r \le \min\left(1, \frac{P(\tilde{x}_i)}{Q(\tilde{x}_i)}\right)$:
     接受(Accept) $\tilde{x}_i$! 这意味着草稿模型猜中了, 或者猜得比大模型期望的还要保守, 继续审查下一个词 $\tilde{x}_{i+1}$.
   * 如果 $r > \min\left(1, \frac{P(\tilde{x}_i)}{Q(\tilde{x}_i)}\right)$:
     拒绝(Reject) $\tilde{x}_i$! 说明小模型在这里盲目冒进或偏离了大模型的意图.
     立即终止后续所有词的验证, 并由大模型从残差分布(Residual Distribution)中重新采样出一个真正合法的替代 Token:
     $$P'(x) = \frac{\max(0, P(x) - Q(x))}{\sum_y \max(0, P(y) - Q(y))}$$
     循环结束.

3. 额外奖励(Bonus Token):
   如果极为幸运, 小模型的 $K$ 个词全部被大模型接受, 大模型就会把其输出的第 $K+1$ 个分布作为免费赠品, 直接采样出第 $K+1$ 个 Token!
   (即: 大模型跑了一次 Forward, 最终产出了 $K+1$ 个 Token).

#### Step 4: 状态清理与回滚(KV Cache Rollback)

如果在第 $m$ 个词被拒绝($m < K$), 说明小模型后续猜的第 $m+1$ 到 $K$ 个词全作废了.
在系统显存中, 必须对 KV Cache 执行裁剪(Truncate), 丢弃废弃步的缓存, 保持状态与实际被接受的文本严格对齐.

### 三、为什么它是数学完全等价的? (无损证明)

很多人初次接触投机采样会怀疑: "小模型采出来的词, 就算经过判定, 整体概率分布不会被小模型带偏吗?"

答案是: 绝对不会, 在数学上是严密恒等的.

对于任意 Token $x$, 最终该位置产出 $x$ 的全概率为:

$$P_{\text{final}}(x) = P(\text{小模型抽中 } x \text{ 且大模型接受它}) + P(\text{小模型抽中的词被拒绝}) \times P(\text{残差重采样抽中 } x)$$

代入采样规则的数学期望公式:

$$P_{\text{final}}(x) = Q(x) \cdot \min\left(1, \frac{P(x)}{Q(x)}\right) + \left(1 - \sum_y \min(Q(y), P(y))\right) \cdot \frac{\max(0, P(x) - Q(x))}{\sum_y \max(0, P(y) - Q(y))}$$

由于对标量恒有:

$$Q(x) \cdot \min\left(1, \frac{P(x)}{Q(x)}\right) = \min(Q(x), P(x))$$

且分母的项可化简抵消, 最终式子变为:

$$P_{\text{final}}(x) = \min(Q(x), P(x)) + \max(0, P(x) - Q(x)) \equiv P(x)$$

无论小模型有多笨, 通过这套拒绝-补偿机制, 输出序列的联合概率分布与纯粹只用 $M_p$ 大模型从头到尾一个字一个字采样得到的分布一模一样. 质量没有丝毫缩水, PPL(困惑度)与 Benchmark 得分完全不变.

### 四、工业界与 vLLM 中的技术演进

在学术界论文提出基础的 Speculative Decoding 后, 工业界(包括 vLLM 等高性能引擎)进行了大规模演进, 目前主要有三种主流形态:

1. 经典双模型投机(Draft-Target Speculation)
   * 如用 LLaMA-3-8B 给 LLaMA-3-70B 做草稿.
   * 优缺点: 命中率高, 但系统需要同时在显存中维护两个完全不同大小的模型, 多卡切分(Tensor Parallelism)配合极度复杂.

2. 无需额外模型的投机: 多头投机(Medusa / Eagle)
   * 不引入小模型, 而是在原始大模型最后一层顶部额外挂载几个轻量级前馈网络头(Medusa Heads).
   * 主模型在输出当前 Token 的同时, 让这些头顺带预测未来第 1、2、3 个 Token. 显存开销极小, 运维简单, 目前被广泛集成.

3. Prompt Lookup / N-Gram 投机
   * 极度轻量: 在编码、文档问答(RAG)、长文本摘要中, 大量未来的 Token 实际上就是原 Prompt 或先前生成的代码块的复制.
   * 直接用极快的字符串匹配从 Context 中"抠出"接下来可能出现的 $K$ 个词进行验证. 没有任何模型推理开销, 零 GPU 额外显存占用.

4. 树状投机(Tree-based Speculative Decoding / SpecInfer)
   * 如果只验证单条线性序列(Line), 一旦第一个词猜错, 后面全废.
   * 现代引擎演进为草稿模型生成候选词树(Tree Attention): 分支探索不同的前缀可能. 大模型利用专门设计的 2D Attention Mask 一次性把整棵树一起验证完, 极大地提高了每轮的期望接受长度(Mean Accepted Length).

---

### 五、投机采样的局限性: 何时它反而会变慢?

作为系统架构师, 必须清醒认识到投机采样并非银弹, 它有非常清晰的性能边界:

1. 大并发、大 Batch 场景下收益递减(甚至为负)
   * 当推理服务处于满载的高并发状态(Batch Size = 128 或更大), 系统本身的瓶颈已经从"显存带宽受限(Memory-Bound)"转移到了"计算单元受限(Compute-Bound)".
   * 此时大模型自身的算力已经被完全吃满, 再插入草稿推理和多 Token 验证, 只会抢占宝贵的 Tensor Core 算力, 导致整体 Throughput(吞吐量)反而下降.
   * 因此, 投机采样的核心适用场景是: 极度追求首字/单请求延迟(Time-To-First-Token & Inter-Token-Latency)的端侧设备、单人高频 Agent 对话或小 Batch 场景.

2. 任务难度过高导致接受率低(Acceptance Rate $\alpha \to 0$)
   * 如果是极高难度的推导(如高难度竞赛数学题), 小模型的猜测与大模型的判定偏差极大, 接受率极低. 如果每轮猜 $K$ 个只接受 0 个, 系统就纯粹白白浪费了小模型推理的耗时, 导致延迟反而上升.

Q: 现代前沿采样策略中有一种结构化采样, 什么是结构化采样, 结构化采样的具体过程是怎么样的, 为什么需要结构化采样?

在现代大模型应用体系(尤其是 AI Agent、工具调用 Tool Calling、企业级数据抽取等)中, 结构化采样(Structured Sampling / Guided Decoding / Constrained Decoding) 是一项革命性的技术.

简单一句话概括其核心: 它利用形式语言理论(如自动机、上下文无关文法), 在每一步自回归采样时动态修剪(Mask)掉所有在语法上非法的 Token, 从而在数学上 100% 保证输出严格符合指定的格式(如 JSON Schema、正则表达式、SQL、Pydantic 模型等).

下面我将从产生背景、实现原理与具体过程、以及系统与工程瓶颈(结合 vLLM / XGrammar 等最新实践)这几个维度进行深入剖析.

---

### 一、为什么需要结构化采样?

在没有结构化采样之前, 开发者通常依靠 提示词工程(Prompt Engineering) 要求模型输出特定格式:

> "请将结果以合法的 JSON 格式输出, 不要输出任何多余的解释, 确保括号闭合."
>

但在工业级生产环境中, 这种方式存在极其致命的缺陷:

1. 概率模型的天然缺陷与语法零容错的矛盾:
   LLM 本质上是基于概率分布预测下一个词的黑盒. 即使最强大的 GPT-4、Claude-3.5 或开源大模型, 在高负载生成下也必然存在小概率的长尾噪声(如遗漏一个逗号、字符串内双引号未转义、多输出了一对 ````json` Markdown 标记). 然而, 下游系统的 `json.loads()`、SQL 执行器或 API 接口是零容错的, 一个字节的语法错误就会导致整个 Agent 管道或自动化流程崩溃.

2. 重试机制(Retry Loop)的巨大代价:
   传统做法是: LLM 输出 $\to$ 校验报错 $\to$ 将错误信息塞回 Prompt $\to$ 让 LLM 重试. 这不仅成倍增加了端到端延迟和 Token 计算成本, 而且在高并发场景下极大地降低了推理系统的吞吐量.

3. 解放模型的推理算力(注意力解耦):
   当模型被迫把宝贵的注意力分散在"我要小心翼翼地闭合括号、缩进、转义冒号"这些纯确定性的语法琐事上时, 其用于逻辑推理的容量就会被稀释. 结构化采样可以将语法保障外包给确定性的状态机, 让模型专注于生成真正的"语义内容"(键对应的值).

---

### 二、结构化采样的具体执行过程

结构化采样是如何在不改动模型权重的前提下, 让大模型乖乖听话的? 它的底层逻辑是: 将形式文法编译为状态机, 与分词器(Tokenizer)取交集, 并在每一步执行 Logit 掩码(Logit Masking).

具体流程可以拆解为以下阶段:

```
 用户输入 (JSON Schema / 正则)
           │
           ▼
┌────────────────────────────────────────┐
│ 1. 离线/预编译阶段 (Compilation)        │
│    文法/Schema ──> 确定性有限状态机(DFA) │
│    词表 Token ──> 状态转移合法性映射    │
└──────────────────┬─────────────────────┘
                   │
                   ▼ (推理阶段进入自回归循环)
┌────────────────────────────────────────┐
│ 2. 获取当前状态 (State Tracking)        │ <──────────┐
│    当前处于状态机节点: S_t               │            │
└──────────────────┬─────────────────────┘            │
                   │                                  │
                   ▼                                  │
┌────────────────────────────────────────┐            │
│ 3. 动态掩码 (Logit Masking)             │            │
│    查询 S_t 允许的合法 Token 集合 V_valid│            │
│    非法 Token Logits 被置为 -inf        │            │
└──────────────────┬─────────────────────┘            │
                   │                                  │
                   ▼                                  │
┌────────────────────────────────────────┐            │
│ 4. 概率计算与采样 (Sampling)            │            │
│    在合法候选集中采样出词 x_t           │            │
└──────────────────┬─────────────────────┘            │
                   │                                  │
                   ▼                                  │
┌────────────────────────────────────────┐            │
│ 5. 状态转移与迭代 (State Transition)    │            │
│    S_{t+1} = δ(S_t, x_t)               │            │
│    若达到终止态且满足条件, 允许 EOS 退出 └────────────┘
└────────────────────────────────────────┘
```

#### Step 1: 文法编译与分词器映射(Precompilation & Automaton Construction)

* 文法转状态机:
  * 如果约束是正则表达式, 计算引擎会将其转化为确定性有限自动机(DFA).
  * 如果约束是复杂的递归结构(如包含嵌套括号的完整 JSON 或编程语言), 则会转化为下推自动机(Pushdown Automaton, PDA)或上下文无关文法(CFG)解析器.
* 跨越分词器与字符的鸿沟(The Tokenization Problem):
  自动机的状态转移通常基于"字符"(Character), 但 LLM 输出的是"分词"(Subword Token, 如 `"name"` 可能是单个 Token, 也可能是 `"` 和 `name` 两个 Token).
  现代引擎(如 Outlines、XGrammar)会在前置阶段将词表中多达十数万个 Token 分别跑一遍状态机, 构建出一张"状态 $\to$ 合法 Token 索引"的跳转表.

#### Step 2: 状态机实时追踪(State Tracking)

假设生成刚开始, 状态机处于初始状态 $S_0$.
随着文本一步步生成, 系统在 CPU 或 GPU 侧同步记录当前自动机走到了哪一个状态节点 $S_t$.

#### Step 3: Logit 掩码计算(Logit Masking)

大模型执行完常规的 Forward Pass, 输出大小为 $[1, |V|]$ 的 Logits 向量(其中 $|V|$ 是词表大小).
在采样之前, 采样器向状态机发起查询:
* 在当前状态 $S_t$ 下, 能合法驱动状态机继续向后走的 Token 集合是什么? 假设为 $\mathcal{V}_{\text{valid}} \subset \mathcal{V}$.
* 将所有非法 Token 的 Logits 强行覆盖为负无穷大:
  $$z'_i = \begin{cases} z_i & \text{if } i \in \mathcal{V}_{\text{valid}} \\ -\infty & \text{if } i \notin \mathcal{V}_{\text{valid}} \end{cases}$$

#### Step 4: 概率归一化与采样(Constrained Softmax & Sampling)

将掩码后的 $z'$ 送入后续常规流程(如 Temperature 缩放、Top-p、或 Greedy 取最大):
$$P_i = \frac{\exp(z'_i)}{\sum_{j \in \mathcal{V}_{\text{valid}}} \exp(z'_j)}$$
由于非法 Token 的 Logit 是 $-\infty$, 它们的采样概率被严格置为 0. 模型绝对不可能挑中任何破坏语法的 Token.

#### Step 5: 状态转移与终止判定(State Advance & EOS Protection)

采样器最终抽出了一个合法的 Token $x_t$:
* 状态机接受 $x_t$, 沿着转移函数推进到下一个状态: $S_{t+1} = \delta(S_t, x_t)$.
* EOS 保护机制: 这是防止"模型生成一半提前中断"的核心! 只有当状态机进入可接受的终止状态(Accepting / Final State)时, 结束符 `<EOS>` 的 Logit 才会被允许保留为正常值; 只要在中间未闭合的状态(比如只写了 `{"name": `), `<EOS>` 就永远被掩码为 $-\infty$, 模型被强制继续往下写, 直到结构完全闭合.

---

### 三、系统工程视角的进阶: 从"学术玩具"到"工业级高吞吐"

早期的结构化采样由于实现粗糙, 在推理引擎中会导致灾难性的性能暴跌(有时吞吐量暴跌 90% 以上). 作为 vLLM 这一层级的系统研发人员, 必须克服以下关键工程瓶颈:

#### 1. 词表遍历带来的 CPU 开销(The Masking Overhead)

* 痛点: 若词表大小 $|V| = 128,000$, 每生成一个词都用 Python/CPU 遍历一遍自动机去判定 128k 个 Token 是否合法, 耗时可能长达数毫秒至十毫秒, 远远超过了 GPU 前向计算本身.
* 解法(XGrammar / Outlines 的创新):
  * 离线/前置 Indexing: 在推理前离线编译 DFA, 直接生成 Bitset(位图)或稀疏压缩表.
  * Fused GPU Kernel: 将构建好的 Bitset 存放在 GPU 显存中, 采样阶段直接在 GPU 核心内完成 Bitwise AND(位运算掩码), 耗时压低到几微秒($\mu s$), 几乎实现零额外延迟开销(Zero Overhead).

#### 2. "跳步"优化(Token Jump / Fast-Forwarding)

在很多结构化输出中, 语法结构本身具有强确定性.
* 例如 JSON 格式中: 在输出完 `"age"` 之后, 下一个 Token 必须是 `": "`(冒号加空格).
* 优化策略: 既然候选词集合中只有唯独这 1 个合法 Token($|\mathcal{V}_{\text{valid}}| = 1$), 系统根本不需要让大模型去跑一遍昂贵的 Forward Pass!
* 推理引擎可以直接触发"快速填充/快进(Token Jump)", 把确定性的文本直接塞入 KV Cache, 连跳几步, 只在大模型需要进行实质内容选择(比如生成具体数字 `25`)时才唤醒 GPU 进行推理. 这使得结构化采样不仅没有变慢, 反而生成速度比无约束生成还要快得多.

### 四、核心采样方式对比与总结

| 采样策略                | 核心目标                       | 是否改变分布           | 典型应用场景                   | 代表技术 / 工具              |
| :---------------------- | :----------------------------- | :--------------------- | :----------------------------- | :--------------------------- |
| 标准采样 (Top-p/Min-p)  | 提升自然度, 平衡多样性与稳定性 | 是(轻微修剪长尾)       | 开放式聊天、写作、文生代码     | vLLM 默认内核                |
| 投机采样 (Speculative)  | 降低解码延迟(加速)             | 否(数学完全无损)       | 追求超低首字/单字延迟的场景    | Medusa, Eagle, Draft-Model   |
| 结构化采样 (Structured) | 保证输出 100% 遵从形式语法     | 是(硬性语义与语法裁剪) | API 调用、Agent、JSON/SQL 抽取 | XGrammar, Outlines, Guidance |

结构化采样的本质, 是将符号逻辑(Symbolic AI)与联结主义大模型(Connectionist AI)在推理运行期进行的一场极优雅的"底层交汇". 它让天生带有随机性与幻觉风险的自回归概率分布, 被牢牢约束在人类确定性的代码和协议轨道之内.

Q: vllm 支持哪些采样方法, 这些方法应该如何使用? 请使用具体的示例进行说明

在 vLLM 中, 采样策略主要由 `SamplingParams` 对象(Python API)或 OpenAI 兼容接口的请求体参数进行配置. vLLM 底层利用高度定制优化的 Fused CUDA/Triton Kernel 实现了连续批处理(Continuous Batching)下的异构采样 -- 这意味着同一个 Batch 内的不同请求, 可以同时运行完全不同的采样参数而互不干扰.

以下将 vLLM 支持的采样方法划分为 5 大核心类别, 并提供可以直接运行的代码示例.

---

### 一、常见采样方法分类一览

1. 确定性采样(Greedy Decoding): `temperature=0.0`
2. 随机截断采样(Stochastic & Truncation):
   * Temperature(温度采样): 调整分布平缓度
   * Top-$p$(Nucleus 采样): 累积概率截断
   * Top-$k$ 采样: 固定名次截断
   * Min-$p$ 采样: 基于最高概率动态自适应截断(现代前沿)
3. 惩罚项采样(Penalties):
   * Repetition Penalty: 乘法惩罚, 抑制重复
   * Frequency Penalty / Presence Penalty: 加法惩罚, 鼓励新词/换话题
4. 多候选与搜索(Multi-Sequence & Search):
   * Best-of-$N$: 并行生成多条并根据 Logprob 择优
   * Beam Search: 传统束搜索(通过 `use_beam_search=True` 开启)
5. 前沿高级采样机制:
   * 结构化采样(Guided Decoding): 正则、JSON Schema、Enum 选择(集成 Outlines / XGrammar)
   * 投机采样(Speculative Decoding): 引擎级双模型/草稿头加速验证

---

### 二、具体使用方法与代码示例

在运行下列代码前, 请确保安装了 vLLM: `pip install vllm`.

#### 1. 基础采样与截断采样(Greedy、Top-p、Top-k、Min-p)

```python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct")
prompts = ["请用一句话解释相对论: "]

# 示例 1: 确定性贪心解码 (适合代码、数学、严谨事实问答)
# 只要 temperature=0, vLLM 底层会自动路由至纯 Argmax 算子
params_greedy = SamplingParams(
    temperature=0.0,
    max_tokens=64
)

# 示例 2: 经典的 Top-p + Top-k 组合采样 (适合日常通用对话)
params_standard = SamplingParams(
    temperature=0.7,
    top_p=0.8,         # 保留累积概率达 80% 的核心词集
    top_k=20,          # 仅在概率前 20 的 Token 中截断
    max_tokens=128
)

# 示例 3: 现代化 Min-p 采样 (比 Top-p 更抗幻觉, 极大保留创造力)
params_min_p = SamplingParams(
    temperature=0.8,
    min_p=0.05,        # 只有概率达到 max_prob * 0.05 的词才会被保留
    max_tokens=128
)

# 统一批量推理 (vLLM 支持一个 Batch 内不同请求混用不同采样参数)
outputs = llm.generate(prompts, sampling_params=params_min_p)
for out in outputs:
    print(out.outputs[0].text)
```

---

#### 2. 惩罚项控制(防重复与复读机)

在开放式长文本创作中, 模型极容易陷入自重复. vLLM 提供了细粒度的惩罚参数:

```python
params_penalties = SamplingParams(
    temperature=0.9,
    # 乘法重复惩罚: >1.0 压制重复, 1.0 代表不开启 (推荐 1.05~1.15)
    repetition_penalty=1.1,

    # OpenAI 兼容的加法惩罚: 范围通常在 [-2.0, 2.0]
    presence_penalty=0.5,     # 只要出现过就扣分, 鼓励谈论新概念
    frequency_penalty=0.3,    # 出现次数越多扣分越狠, 避免频繁唠叨同一个词

    max_tokens=256
)
```

---

#### 3. 多序列输出与 Best-of-$N$ 采样

通过调整 `n` 和 `best_of`, 可以在一次推理请求中采出多条不同的完整回答(常用于强化学习拒绝采样 Rejection Sampling 或写文提供多版本):

```python
params_best_of_n = SamplingParams(
    temperature=0.8,
    top_p=0.95,
    n=2,               # 最终返回 2 条结果给用户
    best_of=5,         # 模型内部并行采样 5 条路径, 按整体累积对数概率(logprob)挑选最好的 2 条
    max_tokens=128
)

outputs = llm.generate(["写一首关于人工智能的短诗"], sampling_params=params_best_of_n)
# 一个 prompt 会对应多个 candidate 输出
for idx, candidate in enumerate(outputs[0].outputs):
    print(f"--- 候选版本 {idx + 1} (Score: {candidate.cumulative_logprob:.2f}) ---")
    print(candidate.text)
```

---

#### 4. 结构化采样(Guided Decoding / Structured Output)

vLLM 原生深度集成了基于状态机掩码的结构化采样, 支持 JSON Schema、Pydantic、正则表达式与选项列表.

```python
from pydantic import BaseModel, Field
from typing import List
from vllm import LLM, SamplingParams

# 定义数据结构
class UserProfile(BaseModel):
    name: str
    age: int
    skills: List[str]

# 示例 A: 强制输出符合 Pydantic 模型的 JSON
params_json = SamplingParams(
    guided_json=UserProfile.model_json_schema(), # 传入 Schema
    guided_decoding_backend="xgrammar",          # 可选 "xgrammar" 或 "outlines", 推荐 xgrammar (高吞吐)
    max_tokens=256
)

# 示例 B: 强制输出符合特定正则表达式 (如只提取中国大陆手机号)
params_regex = SamplingParams(
    guided_regex=r"1[3-9]\d{9}",
    max_tokens=20
)

# 示例 C: 强制在固定列表中选择 (类似分类任务)
params_choice = SamplingParams(
    guided_choice=["积极", "消极", "中立"],
    max_tokens=10
)

prompt = "张三今年 28 岁, 精通 Python 和 Rust, 请提取他的信息. "
outputs = llm.generate([prompt], sampling_params=params_json)
print(outputs[0].outputs[0].text)
# 输出必定是绝对合法的 JSON 字符串, 例如:
# {"name": "张三", "age": 28, "skills": ["Python", "Rust"]}
```

#### 5. 引擎级投机采样(Speculative Decoding)

投机采样并非在单次请求的 `SamplingParams` 里开关, 而是在初始化 `LLM` 引擎或启动服务端时配置的系统架构:

##### 场景 1: 经典大小模型投机(Draft Model)
用一个小模型(如 0.5B)为大模型(如 7B)快速产出草稿:
```python
from vllm import LLM, SamplingParams

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    # 配置草稿小模型
    speculative_model="Qwen/Qwen2.5-0.5B-Instruct",
    num_speculative_tokens=5, # 每次投机验证 5 个候选 Token
    use_v2_block_manager=True
)

# 之后的采样参数正常配置即可, 投机采样数学无损, 会自动加速推理
params = SamplingParams(temperature=0.7, top_p=0.8, max_tokens=128)
```

### 三、生产环境实战: 通过 OpenAI 兼容 API 调用

在实际生产部署中, 我们通常使用 `vllm serve` 启动 HTTP 服务, 客户端通过 `openai` SDK 或 HTTP 请求调用采样配置:

#### 1. 启动服务命令行:
```bash
# 启动时支持设置默认引导解码引擎
vllm serve Qwen/Qwen2.5-7B-Instruct --port 8000 --guided-decoding-backend xgrammar
```

#### 2. Python 客户端调用:
```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="token-vllm")

# 在标准 API 中混用采样策略与结构化输出
response = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[{"role": "user", "content": "请判断这句话的情感倾向: '这家店味道太棒了! '"}],

    # 1. 采样参数
    temperature=0.7,
    top_p=0.9,
    frequency_penalty=0.2,

    # 2. vLLM 特有或结构化扩展参数 (通过 extra_body 传入)
    extra_body={
        "min_p": 0.05,                           # 开启 Min-p
        "guided_choice": ["正面", "负面", "中性"]  # 强制三选一采样
    }
)

print(response.choices[0].message.content) # 输出必定是 "正面"
```

### 四、核心参数选型最佳实践表

| 采样目标                      | 推荐配置组合                                               | 避坑指南                                                                      |
| :---------------------------- | :--------------------------------------------------------- | :---------------------------------------------------------------------------- |
| 数学推导 / 单元测试编写       | `temperature=0.0`                                          | 切勿在此场景滥用 `top_p`, 避免引入不确定性逻辑错误.                           |
| 通用对话 / 摘要提取           | `temperature=0.7`, `min_p=0.05`                            | 相比 `top_p=0.8`, `min_p` 在上下文确定时更不易崩坏.                           |
| 长文本故事写作 / 角色扮演     | `temperature=0.9`, `top_p=0.95`, `repetition_penalty=1.08` | `repetition_penalty` 不宜超过 `1.2`, 否则会导致模型不愿输出常规连接词.        |
| 精准提取 JSON 数据 / 接口调用 | `temperature=0.0` + `guided_json=...`                      | 必须确保结构化采样使用 `xgrammar` 后端, 以避免大型 schema 导致的首字延迟暴增. |
