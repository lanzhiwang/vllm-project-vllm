Q: 假设你是一位精通 LLM 以及 PyTorch 的高级开发人员, 现在我想研究一下注意力机制中关于 KV Cache 的相关问题, 请使用 PyTorch 实现一个简单的模型, 模型中包含 QKV 等结构, 通过模拟前向传播, 观察为什么可以缓存 KV 的值, 请输出完整的代码, 在代码中添加详细的打印和注释, 通过数据说明为什么可以缓存 KV 的值

你好! 要理解 KV Cache 的核心原理, 最直观的方式是抓住因果语言模型(Causal LM)单向自注意力的两个数学本质:

1. 线性投影的独立性: 对于第 $t$ 个 token 的输入向量 $x_t$, 它的 Key 和 Value 分别为 $K_t = x_t W_K$ 和 $V_t = x_t W_V$. 这个投影是逐位置独立计算的, 后面的 token 怎么生成, 完全不影响前面 token 已经计算好的 $K_i$ 和 $V_i$($i < t$).

2. 因果掩码(Causal Mask)的单向性: 在生成第 $t$ 个 token 时, 我们只需要第 $t$ 位置的输出, 而根据因果掩码, 第 $t$ 个位置的 Query $Q_t$ 只会与历史所有的 $K_{0:t}$ 做点积注意力, 并对 $V_{0:t}$ 加权求和.

也就是说: 过去 token 算出来的 Key 和 Value 在后续推理中数值是恒定不变的. 如果每次都把整个序列重新喂给模型, 前面的 $K$ 和 $V$ 就会被反复重算, 造成巨大的算力浪费.

### 输出关键信息解析与总结

当你运行上述代码时, 可以看到以下关键事实:

1. 投影不变性($K$ & $V$ 不变):

   $$K_0 = x_0 W_K$$

   无论后面添加多少个 token, $x_0$ 算出来的特征向量都永远不变.


2. 注意力计算等价性:

   - 无 Cache 方案: 每次输入长度为 $t$ 的完整序列, 计算 $[t \times D] \times [D \times t] \rightarrow [t \times t]$ 的完整注意力矩阵, 经过因果掩码遮蔽后, 仅仅取最后一行输出, 前 $t-1$ 行的注意力计算全被浪费.

   - 有 Cache 方案: 单步只传入当前 $1$ 个 token 计算 $Q_t$(形状 $[1 \times D]$), 历史的 $K_{0:t-1}$ 从缓存取出, 与当前计算的 $K_t$ 拼成 $[t \times D]$. 直接计算 $[1 \times D] \times [D \times t] \rightarrow [1 \times t]$.

   - 最终得到的注意力分布数值完全一致, 输出完全相同.

3. 复杂度差异:

   - 无 Cache: 生成 $N$ 个 token, 总前向计算量是 $\sum_{t=1}^N \mathcal{O}(t^2) \approx \mathcal{O}(N^3)$(算上投影是 $N \times$ 序列长度重算).

   - 有 Cache: 避免了 $W_Q, W_K, W_V$ 的历史重复投影, 矩阵投影运算从 $\mathcal{O}(N^2)$ 降到了 $\mathcal{O}(N)$; 注意力计算整体降为 $\mathcal{O}(N^2)$. 这就是典型的以空间换时间策略.

Q: 上述代码中有 [batch_size, seq_len, d_model] 相关的内容, 请详细说明一下他们的含义, 通过举例说明现实世界中的真实文字是如何转成数字的

在深度学习中, 计算机是无法直接"理解"汉字或英文单词的, 它只能做浮点数的矩阵运算.

张量形状 `[batch_size, seq_len, d_model]` 是 Transformer/LLM 处理文本时最基础的"三维几何结构".

---

### 一、三个维度的核心含义

我们可以把处理文本想象成一本装订好的活页夹:

| 维度名称     | 中文含义              | 通俗比喻                                               | 决定因素                                          |
| :----------- | :-------------------- | :----------------------------------------------------- | :------------------------------------------------ |
| `batch_size` | 批大小                | 同时处理的句子/文章篇数(活页夹里的第几页)              | 由显卡显存大小与并发需求决定.                     |
| `seq_len`    | 序列长度              | 这一篇内容里包含的单词/字元(Token)总数(每一页上有几行) | 由文本长短决定(不足通常补 0, 超长截断).           |
| `d_model`    | 特征维度 / 词向量维度 | 每个 Token 被表示为多少个维度的特征数字(每一行写多长)  | 由模型架构决定(如 LLaMA-7B 是 4096, BERT 是 768). |

---

### 二、现实世界中的文字, 是如何一步步变成 `[B, S, D]` 的?

我们通过一个极其具象的极简例子, 还原真实大模型的全流程.

假设我们现在有 2 句话要同时送入模型:

* 句子 1: `"我 喜欢 猫"`
* 句子 2: `"你 喜欢 狗"`

#### 第一步: Tokenization(分词)

大模型不能直接处理字符串, 首先会借助分词器(Tokenizer)把整句话切分成最小语义单元(Token).

* 句子 1 $\rightarrow$ `["我", "喜欢", "猫"]`(长度为 3)
* 句子 2 $\rightarrow$ `["你", "喜欢", "狗"]`(长度为 3)

---

#### 第二步: 查词表转为数字 ID(Token IDs)

分词器内部有一本字典(Vocabulary, 词表), 每个词对应一个固定的整数编号(通常词表大小是 32,000 ~ 150,000 不等).

假设我们的极简词表如下:

```bash
{
    "[PAD]": 0,   # 填充符
    "我":   101,
    "你":   102,
    "喜欢": 205,
    "猫":   308,
    "狗":   309
}
```

查表转换后, 两句话变成了离散整数矩阵:

* 句子 1 $\rightarrow$ `[101, 205, 308]`
* 句子 2 $\rightarrow$ `[102, 205, 309]`

此时我们把它们打包成一个二维张量(Tensor):

```python
input_ids = [
    [101, 205, 308],  # 句子 1
    [102, 205, 309]   # 句子 2
]
```
此时的形状为 `[batch_size, seq_len] = [2, 3]`.

* `batch_size = 2`: 处理了 2 个句子.
* `seq_len = 3`: 每个句子有 3 个词.

> 疑问: 为什么不能直接拿着整数 `101, 205, 308` 扔给神经网络算注意力?
> 解答: 整数大小没有数学连续语义! 数字 102 并不比 101 "大一倍", 整数不能反映"猫"和"狗"都是宠物的语义相似度. 因此必须进入第三步 -- 词嵌入(Embedding).
>

---

#### 第三步: 词嵌入(Embedding Lookup)

模型底层有一张很大的可学习权重表, 叫做 Embedding 矩阵.

* 矩阵的行数是词表大小(Vocab Size).
* 矩阵的列数就是 `d_model`(每个词用多少个浮点数来刻画其语义, 假设我们设为 4).

这 4 个数字可以理解为提取的特征(例如: [生命属性, 情感色彩, 动作性, 语法属性]):

| 词 ID      | 对应的 `d_model` 向量 (长度为 4) | 形象理解                          |
| :--------- | :------------------------------- | :-------------------------------- |
| 101 (我)   | `[ 0.12, -0.45, 0.88, 0.03 ]`    | 人称代词的语义向量                |
| 102 (你)   | `[ 0.15, -0.42, 0.85, 0.01 ]`    | 人称代词(数值与"我"比较接近)      |
| 205 (喜欢) | `[-0.05, 0.92, 0.11, -0.34 ]`    | 心理/动词特征                     |
| 308 (猫)   | `[ 0.78, 0.23, -0.65, 0.51 ]`    | 动物/宠物特征                     |
| 309 (狗)   | `[ 0.75, 0.25, -0.60, 0.55 ]`    | 动物/宠物特征(数值与"猫"极其接近) |

---

#### 第四步: 拼接成三维张量 `[batch_size, seq_len, d_model]`

经过 Embedding 层一查, 原本只有整数的两个句子, 被扩展成了真正的浮点数三维张量:

```bash
句子 1 (batch_index = 0):
  "我"   -> [ 0.12, -0.45, 0.88, 0.03 ]   (seq_index = 0)
  "喜欢" -> [-0.05, 0.92, 0.11, -0.34 ]   (seq_index = 1)
  "猫"   -> [ 0.78, 0.23, -0.65, 0.51 ]   (seq_index = 2)

句子 2 (batch_index = 1):
  "你"   -> [ 0.15, -0.42, 0.85, 0.01 ]   (seq_index = 0)
  "喜欢" -> [-0.05, 0.92, 0.11, -0.34 ]   (seq_index = 1)
  "狗"   -> [ 0.75, 0.25, -0.60, 0.55 ]   (seq_index = 2)
```

此时的张量形状就是:

$$\mathbf{[batch\_size=2,\ seq\_len=3,\ d\_model=4]}$$

### 四、结合前面的 KV Cache 理解 `seq_len` 的变化

理解了这个三维形状后, 你就能更清晰地看出 KV Cache 到底优化了什么:

1. Prompt 阶段(Prefill 首次计算):
   输入你的完整提示词, `x` 的形状是 `[1, 10, d_model]`(`seq_len = 10`), 此时一次性把这 10 个词的 K、V 算出来存进缓存.

2. 解码阶段(Decode 逐字吐字):

   * 不用 KV Cache: 第 11 步输入全量序列 `[1, 11, d_model]`, 第 12 步输入 `[1, 12, d_model]` ...... `seq_len` 不断变大, 每一步都在为以前所有词重复做 `Linear` 变换.

   * 使用 KV Cache: 第 11 步传给模型的 `x` 形状仅仅是 `[1, 1, d_model]`(`seq_len` 始终为 1)! 单步计算只投影最新的这 1 个词, 剩下历史的 $N$ 个词的特征全部从显存里的 KV 缓存拼接读取.

#### 3. 为什么 Q 数值相同却不缓存? (通俗类比)

可以把这个过程想象成在图书馆查资料:

- $K$(Key, 图书索引卡): "我"、"爱"、"吃"这三本书的索引信息. 随着藏书变多, 新来的书也需要建立索引.
- $V$(Value, 图书正文内容): "我"、"爱"、"吃"的具体内容.
- $Q$(Query, 读者借书时提出的问题):
  - 第 1 步读者想知道"吃"后面该接什么, 读者提出了问题 $Q_{吃}$;
  - 找完答案得到"面"之后, 这个问题 $Q_{吃}$ 就已经作废了!
  - 第 2 步, 读者想知道"面"后面接什么, 读者提出了全新的问题 $Q_{面}$.
  - $Q_{面}$ 去翻阅历史所有的索引卡 $K_{我}, K_{爱}, K_{吃}, K_{面}$, 提取内容 $V_{我}, V_{爱}, V_{吃}, V_{面}$.
  - 过去提过的老问题 $Q_{我}, Q_{爱}, Q_{吃}$ 留在那里毫无意义. 因此, 模型只缓存藏书的索引($K$)和内容($V$), 从不需要缓存提问记录($Q$).

### 第一步: 计算原始相关度并缩放(scores)

```python
scores = torch.matmul(Q, K.transpose(-2, -1)) / (self.d_model**0.5)
```

#### 1. 计算过程

1. 转置 $K$: 将 $K$ 的最后两个维度对调, 形状从 `[1, 3, 4]` 变为 `[1, 4, 3]`.

2. 矩阵乘法 $Q \times K^T$:

   * 形状变换: `[1, 3, 4]` $\times$ `[1, 4, 3]` $\rightarrow$ `[1, 3, 3]`.

   * 计算本质是两两 Token 做向量点积(代表文本之间的关联程度):

     * $Q_0 \cdot K_0 = 1\times 1 + 0\times 0 + 1\times 0 + 0\times 0 = 1.0$

     * $Q_0 \cdot K_1 = 0.0$

     * $Q_0 \cdot K_2 = 1\times 2 + 0\times 0 + 1\times 2 + 0\times 0 = 4.0$

     * 依此类推......得到未缩放的矩阵:

       $$
       \begin{bmatrix} 1.0 & 0.0 & 4.0 \\ 0.0 & 4.0 & 0.0 \\ 1.0 & 2.0 & 4.0 \end{bmatrix}
       $$

3. 除以 $\sqrt{d_{model}} = 2.0$(防止点积数值过大导致梯度消失):

   * 每个数字除以 2.

#### 2. 形状与最终数值

* 变量形状: `[1, 3, 3]`

* 数值结果:

```bash
scores = tensor([[[ 0.5,  0.0,  2.0 ],   # Token 0 ("我") 去看 "我", "爱", "吃" 的分数
                  [ 0.0,  2.0,  0.0 ],   # Token 1 ("爱") 去看 "我", "爱", "吃" 的分数
                  [ 0.5,  1.0,  2.0 ]]]) # Token 2 ("吃") 去看 "我", "爱", "吃" 的分数
  ```

---

### 第二步: 生成因果掩码(mask)

```python
mask = torch.triu(torch.full((seq_len, seq_len), float("-inf")), diagonal=1)
```

#### 1. 计算过程

因果语言模型必须保证前面的词不能看到未来的词:

1. `torch.full((3, 3), -inf)`: 生成一个全为 $-\infty$ 的 $3 \times 3$ 矩阵.

2. `torch.triu(..., diagonal=1)`: 保留严格上三角部分(对角线偏移 1), 其余位置填 0.

#### 2. 形状与最终数值

* 变量形状: `[3, 3]`

* 数值结果:

```bash
mask = tensor([[ 0.0, -inf, -inf],   # 第0个词: 能看自己(0), 不能看后面(-inf)
               [ 0.0,  0.0, -inf],   # 第1个词: 能看前两个(0), 不能看第3个(-inf)
               [ 0.0,  0.0,  0.0]])  # 第2个词: 全部能看(全 0)
```

---

### 第三步: 掩码相加(masked_scores)

```python
masked_scores = scores + mask
```

#### 1. 计算过程

广播机制下, 将 `scores` 和 `mask` 对应元素相加:

* 任何实数 $+ 0.0 =$ 原数不变(保留).

* 任何实数 $+ (-\infty) = -\infty$(未来信息被强制涂黑屏蔽).

#### 2. 形状与最终数值

* 变量形状: `[1, 3, 3]`

* 数值结果:

```bash
masked_scores = tensor([[[  0.5,  -inf,  -inf ],  # "我" 看未来被遮蔽
                        [  0.0,   2.0,  -inf ],  # "爱" 看 "吃" 被遮蔽
                        [  0.5,   1.0,   2.0 ]]]) # "吃" 可以看所有历史词
```

---

### 第四步: 计算注意力权重(attn_weights)

```python
attn_weights = F.softmax(masked_scores, dim=-1)
```

#### 1. 计算过程

沿每行的最后一个维度(`dim=-1`)做 Softmax 归一化:

$$\text{Softmax}(z_i) = \frac{e^{z_i}}{\sum e^{z_j}}$$

数学特性: $e^{-\infty} = 0$, 所以被遮挡的未来词计算权重直接严格等于 0.

* 第 0 行 `[0.5, -inf, -inf]`:

  $$e^{0.5} \approx 1.65,\quad e^{-\infty} = 0,\quad e^{-\infty} = 0$$

  权重分配: $\frac{1.65}{1.65} = \mathbf{1.0}$, 其余为 $\mathbf{0.0}$.

* 第 1 行 `[0.0, 2.0, -inf]`:

  $$e^{0.0} = 1.0,\quad e^{2.0} \approx 7.39,\quad \text{和} \approx 8.39$$

  权重分配: $\frac{1.0}{8.39} \approx \mathbf{0.119}$, $\frac{7.39}{8.39} \approx \mathbf{0.881}$, 未来词为 $\mathbf{0.0}$.

* 第 2 行 `[0.5, 1.0, 2.0]`:

  $$e^{0.5} \approx 1.65,\quad e^{1.0} \approx 2.72,\quad e^{2.0} \approx 7.39,\quad \text{和} \approx 11.76$$

  权重分配: $\frac{1.65}{11.76} \approx \mathbf{0.140}$, $\frac{2.72}{11.76} \approx \mathbf{0.231}$, $\frac{7.39}{11.76} \approx \mathbf{0.629}$.

#### 2. 形状与最终数值

* 变量形状: `[1, 3, 3]`

* 数值结果:

```bash
attn_weights = tensor([[[ 1.000,  0.000,  0.000 ],  # "我" 100% 关注自己

                        [ 0.140,  0.231,  0.629 ]]]) # "吃" 关注 "我"(14%), "爱"(23.1%), "吃"(62.9%)
```

### 第二步: 前馈神经网络(FFN / MLP)

```python
ffn_out = self.ffn(attn_out)
```

#### 1. 计算过程

大模型的 FFN 通常由两层线性层和一个激活函数组成:

$$\text{FFN}(x) = \text{ReLU}(x W_1 + b_1) W_2 + b_2$$

1. 升维映射: 通过 `Linear(4, 8)` 将特征维度从 4 扩展到 8.

   * 形状变化: `[1, 3, 4]` $\rightarrow$ `[1, 3, 8]`

2. 非线性激活: 经过 `ReLU`(所有负数变成 0, 正数保留), 赋予模型非线性推理能力.

3. 降维映射: 通过 `Linear(8, 4)` 将维度压缩回 4.

   * 形状变化: `[1, 3, 8]` $\rightarrow$ `[1, 3, 4]`

> 架构含义:
> - Self-Attention 负责横向跨词沟通("吃"知道了前面有"我"和"爱");
> - FFN 负责纵向深度加工(模型在大脑里把"我爱吃"的信息融会贯通, 思考接下来应该接某种食物).
>

#### 2. 形状与最终数值

* 变量形状: `[1, 3, 4]`

* 数值结果:

```bash
ffn_out = tensor([[[ 0.45, -0.15,  0.88,  0.12 ],   # Token 0

```

### 三、核心灵魂拷问: 为什么 Q 也重复了, 却绝不缓存 Q?

终端对比显示:

```bash
3. [Q 矩阵对比]:
--> Q 是否完全一模一样? True
```

既然第二次前 3 个 Token 的 Q 也一模一样, 为什么说 "缓存 Q 纯属浪费显存"?

#### 1. 从"预测下一个词到底需要什么"看数学公式

我们在第二轮的目标是预测第 5 个字(即 `"面"` 后面的字).
为了预测第 5 个字, 根据 Decoder-only 自回归规则, 我们只需要且仅需要第二轮计算结果的最后一行(索引 3, 即 `"面"`).

请看这一行是怎样算出来的数学公式:

$$\text{Output}_{\text{面}} = \text{FFN}\left( W_{out} \sum_{j=0}^{3} \text{attn}_{3, j} \cdot V_j \right)$$

其中注意力权重为:
$$\text{attn}_{3, j} = \text{Softmax}\left( \frac{\mathbf{Q_3} \cdot \mathbf{K_j}^T}{\sqrt{d}} \right),\quad j \in \{0, 1, 2, 3\}$$

我们把参与算式的所有变量列一个清单:
1. $Q$ 参与了谁?
   * 只有 $Q_3$(`"面"` 自己的 Q)!
   * $Q_0$ ("我")、$Q_1$ ("爱")、$Q_2$ ("吃") 去哪了?
   * 它们根本没有出现在计算新词的任何一条算式中! 完全没有!
2. $K$ 参与了谁?
   * $K_0$ ("我"), $K_1$ ("爱"), $K_2$ ("吃"), $K_3$ ("面") —— 全部都在参与计算(用来和 $Q_3$ 做点积).
3. $V$ 参与了谁?
   * $V_0$ ("我"), $V_1$ ("爱"), $V_2$ ("吃"), $V_3$ ("面") —— 全部都在参与计算(按权重加权求和).

---

#### 2. "提问者" 与 "资料库" 的角色本质

用现实业务逻辑作比喻:
* $Q$(Query)是[提问者提的问题]:
  * 在第 1 轮中, "吃"问了一句: "我爱吃后面该接什么? "($Q_{吃}$). 模型根据这个提问找到了"面", 任务已经完成了.
  * 在第 2 轮中, 轮到"面"来提问: "我爱吃面后面该接什么? "($Q_{面}$).
  * 此时, "面"去查资料, 它需要知道"吃"之前提过什么问题吗? 根本不需要!  它只关心自己的问题.
  * 因此, $Q_{吃}$ 的生命周期在生成"面"的那一瞬间就彻底终结了, 它的历史使用价值为 0.
* $K$(Key)是[图书馆每本书的索引], $V$(Value)是[书里的内容]:
  * "面"来查资料时, 它需要翻看书库里所有的书(从第 1 本"我", 到第 2 本"爱", 到第 3 本"吃", 以及它自己"面").
  * 以后再来第 5 个字、第 6 个字, 也依然必须翻看前面所有的书!
  * 所以过去的 $K$ 和 $V$ 会被未来的每一个 Token 反复、高频地查询.

---

#### 3. 张量生命周期与使用频次对比

| 张量名称 | 首次生成时机  | 在后续生成第 $t+1, t+2, \dots$ 步中的使用频次     | 是否有缓存价值?              |
| :------- | :------------ | :------------------------------------------------ | :--------------------------- |
| $Q_t$    | 第 $t$ 步生成 | 0 次(后续任何步骤完全不参与计算)                  | ❌ 坚决不存(存了也是白占显存) |
| $K_t$    | 第 $t$ 步生成 | 永久使用(未来生成的每个新 Token 都要与它点积)     | 必须缓存 (KV Cache)          |
| $V_t$    | 第 $t$ 步生成 | 永久使用(未来生成的每个新 Token 都要按权重抽取它) | 必须缓存 (KV Cache)          |

### 四、工业级 KV Cache 是如何执行第二轮的?

看完上面的数学本质, 你就能明白工业级推理(如 vLLM、HuggingFace、TensorRT-LLM)在第二轮到底是怎么跑的:

在第二轮中, 工业实现根本不会把输入搞成 `[1, 4]`, 而是只送入新增的那 1 个词:
```python
# 工业级推理第 2 轮输入: 仅仅是当前这 1 个字
input_id = torch.tensor([[4]])  # 形状: [1, 1], 即 "面"

# 1. 此时模型计算出的 Q, K, V 形状全都是 [1, 1, 4]!
# 根本不去算前 3 个字的 Q, K, V, 从而直接节省了 75% 的线性投影算力!
q_new = w_q(x)  # Q["面"]: [1, 1, 4]
k_new = w_k(x)  # K["面"]: [1, 1, 4]
v_new = w_v(x)  # V["面"]: [1, 1, 4]

# 2. 拿出第一轮存好的 K_cache, V_cache (形状为 [1, 3, 4]), 拼接最新的 k_new, v_new
k_all = torch.cat([k_cache, k_new], dim=1)  # 形状变为 [1, 4, 4]
v_all = torch.cat([v_cache, v_new], dim=1)  # 形状变为 [1, 4, 4]

# 3. 注意力矩阵计算: [1, 1, 4] @ [1, 4, 4]^T -> [1, 1, 4]
# 仅仅算了一行 [0.232, 0.254, 0.287, 0.228]!
attn_weights = softmax(q_new @ k_all.transpose(-1, -2) / 2.0)

# 4. 加权求和: [1, 1, 4] @ [1, 4, 4] -> [1, 1, 4], 直接送入 FFN 预测第 5 个字!
```

### 总结
1. Q 之所以重复, 是因为没有 KV Cache 时全量重新输入了老文本做投影.
2. Q 之所以不缓存, 是因为在因果生成中, 只有最新的那 1 个 Token 在扮演 Query 的角色; 历史的 Q 在产生新 Token 的数学公式中出现次数恒为 0.
3. KV Cache 的终极精髓, 就是把 Q 的输入长度永久固定为 1, 只把 $K$ 和 $V$ 随时间向后拼接延长.
